# Политика совместимости PHP и разрешения зависимостей

## Цель

Первый самостоятельный P0-этап технического долга: сделать проверяемыми заявления о поддержке PHP и способ запуска проверок на разных версиях без изменения публичного API.

## Исходные факты

- `composer.json` задаёт `>=7.3 || ^8.0`, что эквивалентно `>=7.3`: верхней границы нет, но это не подтверждает прохождение тестов на всех будущих версиях PHP.
- Штатная PR-матрица `.github/workflows/CI.yml` содержит PHP 7.3, 7.4 и 8.0–8.3. PHP 8.4/8.5 отсутствуют. На момент исследования PHP 7.3 и 8.5 прошли локальные unit-проверки в Docker, но не всю матрицу.
- `composer.lock` игнорируется Git по текущему выбору проекта. Локальный lock от новой версии PHP может помешать `composer install` на PHP 7.3. Без lock Composer разрешает зависимости под фактическую платформу и создаёт локальный lock. [Composer рекомендует](https://getcomposer.org/doc/02-libraries.md#lock-file) хранить lock для воспроизводимой разработки библиотеки и отдельно запускать unlocked-проверки; решение о схеме lock/матрицы требует следующего этапа.
- Интеграция требует тестового стенда devtr6 и отдельного ключа; обычная PR-матрица её не запускает. По правилам `AGENTS.md` локальный результат интеграции обязателен для PR с изменениями исполняемого кода или тестов.

## Объём и приёмка

1. README различает заявленную нижнюю границу PHP, текущую CI-матрицу и целевой диапазон 7.3–8.5. PHP 8.4/8.5 нельзя называть подтверждённой поддержкой до зелёной матрицы.
2. README объясняет текущий выбор игнорировать lock, риск этого выбора, как выполнять проверку в чистой копии для каждой версии и как фиксировать версии PHP, Composer, состав разрешённых пакетов, команды и exit codes.
3. Документируется текущее правило Composer: использовать стабильную ветку 2.x, совместимую с выбранной версией PHP, и записывать фактическую версию. Правило зависит от времени и не делает сборку воспроизводимой без lock; pin и матричные jobs — отдельный этап.
4. `Roadmap.md`, `Tasks.md` и README согласованы с реальным CI. Код, `composer.json`, CI-конфигурация и публичные сигнатуры/сериализация не меняются.
5. Выполнить локальные проверки в чистых копиях на PHP 7.3 и 8.5, указав точные команды, версии PHP/Composer, состав зависимостей (`composer show --locked`), hash локального lock, exit codes и ограничения. До правок README выполняется независимое ревью PRD, после правок — независимое ревью diff.

## Вне объёма

Расширение CI до 8.5, фиксация конкретных версий Composer и зависимостей, изменение runtime-минимума, интеграция и изменение пользовательского API. Это отдельные этапы.

## Ревью и проверки

20.10.2026 независимый агент `/root/prd_review` выполнил read-only ревью до правок README. Приняты замечания: `composer.lock` — выбор проекта, а не обязательное свойство библиотек; `>=7.3 || ^8.0` не ограничивает верхнюю версию; в приёмке нужны чистые платформенные прогоны и состав зависимостей; правило выбора Composer не является pin. PRD уточнён до реализации. Отдельное замечание о разных наборах пакетов на 7.3 и 8.5 будет отражено в результатах.

### Фактические проверки

Проверки 20.10.2026 выполнялись в двух отдельных каталогах `/tmp`: в каждом `git archive HEAD` базовой ветки был распакован в чистый каталог `vetmanager-rest-api` без игнорируемого lock. Проверяемый PR меняет только документацию; исполняемый код совпадает с этим HEAD. Для каждого каталога выполнены `make all PHP_VERSION=<версия>`, `docker run --rm vetmanager-rest-api:<версия> php -v`, аналогичная команда с `composer --version`, `docker run --rm -v "$PWD":/app -w /app vetmanager-rest-api:<версия> composer validate --strict`, `composer show --locked --no-ansi` и `sha256sum composer.lock`. Отдельные чистые копии использованы для `composer install --no-dev --no-interaction --prefer-dist` и `composer check-platform-reqs --no-dev`.

| Проверка | PHP 7.3 | PHP 8.5 |
| --- | --- | --- |
| Фактические PHP / Composer | 7.3.33 / 2.10.3 | 8.5.11 / 2.10.3 |
| `make all` | exit 0; style, PHPStan, 47 tests / 48 assertions, coverage 92,54% | exit 0; те же 47 / 48 и 92,54% |
| `composer validate --strict` | exit 0 | exit 0 |
| `composer show --locked --no-ansi` | exit 0; [63 пакета](reviews/php-7.3-resolved-packages.txt) | exit 0; [62 пакета](reviews/php-8.5-resolved-packages.txt) |
| SHA-256 созданного `composer.lock` | `c1e5cdd116fc52c2a5d5c13b8951aad2b30af41df691f47cd9cdf554dbad4006` | `d4da93a5a8627e953edf4f638694f1e1d93d2b9186da87894bdd7bbbb48cf9c8` |
| `composer install --no-dev` / `composer check-platform-reqs --no-dev` | exit 0 / 0 | exit 0 / 0 |

Разница зависимостей существенна: например, на 7.3 разрешился `doctrine/instantiator` 1.5.0 и Symfony 5.4, на 8.5 — `doctrine/instantiator` 2.1.0 и Symfony 8.1. Локальный прогон не является результатом CI. Промежуточные версии PHP здесь не проверялись; интеграция на devtr6 не запускалась, так как исполняемый код и тесты не менялись. `make all` выводит нефатальное предупреждение о повторной загрузке Xdebug.
