# PR #28: имена публичного API для именованных путей

## Цель

Убрать из исполняемого PHP API привязку к формату документации OpenAPI. Снимок OpenAPI остаётся источником проверки списка путей, но вызывающий код работает с маршрутом сервера, а не с протоколом спецификации.

## Контракт

- До слияния PR заменить `URI\OpenApiPath` на `URI\NamedPath`, а `openApiPath()` на `namedPath()`. Это новые символы только ветки PR; опубликованного контракта с ними ещё нет. Старые символы из `main` сохраняются.
- `NamedPath::TEMPLATES` содержит те же 19 точных шаблонов маршрутов. Регистр пути и параметров, `asString()`, кодирование сегментов и ошибки для неверных параметров сохраняются. Код не читает YAML/JSON во время исполнения.
- Оставить точные серверные имена `Model`: ранее доступные 51 имя и 14 подтверждённых вариантов, включая заглавные сегменты. Не преобразовывать регистр по соглашению PHP: изменение строки запроса могло бы сломать серверный маршрут. PHP-символы именовать в стиле проекта: `NamedPath` (PascalCase), `namedPath()` (camelCase), пространство `URI` как уже существующее.
- Обновить все ссылки на новый PHP API в тестах, README, матрице и текущей очереди задач. Исторические результаты прежних ревью и проб оставить с пояснением о переименовании.

## Проверки и гейты

Независимое ревью этой постановки до кода и независимое ревью итогового diff. Затем `python3 -I scripts/check_openapi_contract.py`, `make all PHP_VERSION=8.3`, чистые копии для PHP 7.3 и 8.5, `make integration` только на devtr6, `git diff --check`, CI всех jobs на итоговом SHA. Записать точные коды выхода и ограничения. Сливать PR только после зелёного CI и отсутствия блокирующих замечаний.
