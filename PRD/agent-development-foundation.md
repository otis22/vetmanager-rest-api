# PRD: основа агентской разработки

## Цель

Сделать работу с небольшой PHP-библиотекой воспроизводимой для агента: ясная очередь, проверяемая приёмка, проектные правила и рабочая Docker-сборка. База ветки — `4947abe`; работа не относится к PR #25.

## Проверенные исходные факты

- В checkout не было `AGENTS.md`, `Roadmap.md`, `Tasks.md` и `PRD/`; рабочая копия перед правками была чистой.
- `composer.json`: PHP `>=7.3 || ^8.0`, PHPUnit `^9.5`, PHPStan `^1.9` с уровнем 8 в script, PHPCS с PSR-12.
- `Makefile`: PHP 8.3 по умолчанию; `all` = build, install, style, static-analyze, unit. Integration — отдельная цель с `.env`.
- CI проверяет PHP 7.3–8.3 командами Composer и запускает integration с секретами CI. В README до правки были указаны PHP 8.1 по умолчанию и отсутствующие цели `security` / `coverage`.
- `make build PHP_VERSION=8.3` до правки завершался с exit 2 (`/bin/sh: VERSION: parameter not set`): `ARG VERSION` был объявлен только до `FROM` и не был доступен в `RUN`.

## Scope

1. Ввести короткий `AGENTS.md` с соглашениями, фактическими командами и минимальным процессом: PRD до нетривиальной работы, независимое ревью PRD и diff, запись результатов проверок.
2. Ввести единую очередь в `Roadmap.md`, приёмку и зависимости в `Tasks.md`.
3. Переобъявить `ARG VERSION` после `FROM`, чтобы Docker `RUN` мог выбрать ветку Xdebug по версии PHP.
4. Исправить подтверждённые расхождения раздела разработки README.

## Вне scope

Функциональные изменения публичного API, изменение матрицы PHP или порога покрытия, production-интеграции, переработка CI и работа по PR #25. Тяжёлые правила production-сервиса `vetmanager-mcp` сюда не переносятся.

## Ограничения и риски

- Синтаксис PHP-кода должен оставаться совместимым с 7.3. Проверка только на 8.3 не доказывает совместимость всей матрицы.
- Docker-сборка зависит от внешних образов, Alpine, PECL и Composer. Проверка PHP 7.3 после исправления `ARG` обнаружила независимый блокер: в Alpine 3.15 отсутствует `icu-data-full`. Он вынесен в N1, чтобы не смешивать инфраструктурную совместимость всей матрицы с точечным исправлением.
- Интеграционные тесты требуют тестового API и учётных данных. Отсутствие данных фиксируется как ограничение, не как успешная проверка.
- Независимое ревью проводит отдельный агент или рецензент; исполнитель разбирает его замечания перед коммитом.

## Критерии приёмки

- Документы согласованы между собой, ссылки и статусы указывают на текущий этап, будущие задачи не выдаются за выполненные.
- `make build PHP_VERSION=8.3` проходит как минимум ранее падавший шаг; конечный результат и возможные новые блокеры записаны вместе с exit code.
- Доступные проверки стиля, анализа, unit и покрытия выполнены либо явно описана причина недоступности; интеграция без учётных данных не запускается.
- PRD и diff независимо рассмотрены, важные замечания закрыты или обоснованно отклонены.
- Локальный commit содержит только изменения этого этапа и требуемый trailer; push и PR отсутствуют.
