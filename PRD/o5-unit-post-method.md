# O5: узкая отправка JSON для Unit — 2026-10-26

## Контекст и решение

Исходная матрица — `PRD/o5-schema-evidence-2026-10-26.md`. После её составления
один минимальный JSON `POST /rest/api/Unit` на devtr6 вернул HTTP 201 и объект
`data` с ключами `totalCount`, `unit`. Временная запись Unit ID 48 с уникальным
техническим маркером впоследствии удалена; GET вернул пустую коллекцию, а
Redash DS 6 подтвердил нули по ID и маркеру. Это доказывает приём одного
минимального JSON-тела и успешное создание записи. PUT не выполнялся.

В этом PR добавляется только опциональный `Methods\Unit::post()` для отправки
переданного вызывающим кодом массива как JSON через Guzzle. Метод не проверяет
поля, не разбирает ответ и не выполняет запрос сам по себе. Существующие
`uri()`, `Builder`, заголовки и методы остаются без изменений. Сигнатура:
`__construct(ClientInterface $client)` и
`post(Headers $headers, array $body): ResponseInterface`.

Маршрут — `uri('Unit')->asString()`; `ClientInterface::request()` получает
`'POST'` и опции ровно `headers => $headers->asKeyValue()`, `json => $body`.
Настройки клиента, исключения, код ответа и его тело передаются без обработки.
Массив payload намеренно не объявлен валидированным. Вызывающий код отвечает
за разрешение на запись, состав тела и жизненный цикл записи.

## Граница доказательств и матрица

В `operation-support.json` только у `post_rest_api_Unit` меняется
`http_method_support` с `none` на `unit_post`. `schema_support` остаётся `none`
для всех 137 операций. `scripts/check_openapi_contract.py` сверяет класс и
эту запись. Матрица схем указывает POST как «минимальный JSON принят», PUT
как «не проверено». `required`, `nullable`, enum, диапазоны, чужие поля и
отклонённые тела остаются недоказанными. Универсальный `SchemaValidator` и
PUT метод не добавляются.

## Приёмка

- Unit-тест с Guzzle mock проверяет точный метод, URI, JSON, Content-Type,
  заголовок авторизации и возврат исходного ответа без разбора.
- Отдельные тесты проверяют передачу HTTP 4xx/5xx через настройки Guzzle и
  отсутствие клиентской валидации дополнительных полей.
- Проверить, что матрица отличается от исходной ровно одним
  `http_method_support`, а `schema_support` нигде не меняется.
- `python3 -I scripts/check_openapi_contract.py`, `make all PHP_VERSION=8.3`,
  локальный `make integration` только на devtr6, `git diff --check`.
- Независимое ревью этого PRD до кода и diff после кода; CI по PHP 7.3–8.5
  для итогового SHA. Новых записей или изменений во внешних данных нет.
