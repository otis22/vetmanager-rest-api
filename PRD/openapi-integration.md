# Интеграция публичной OpenAPI и очередь контрактных работ

## Цель

Добавить в репозиторий воспроизводимый снимок публичной спецификации VetManager REST API и составить проверяемую очередь расширения библиотеки без изменения её текущего публичного поведения.

## Объём и приёмка

1. Положить неизменённые YAML и JSON из указанного коммита в `docs/openapi/`, сохранить уведомление о лицензии и атрибуцию; README ведёт к локальной копии, публикации и коммиту источника.
2. В `Roadmap.md` и `Tasks.md` добавить отдельный этап с подтверждёнными пробелами, гипотезами, зависимостями и приёмкой. Учесть имена моделей, нестандартные пути, методы, схемы, ошибки, валидацию, тесты и безопасное обновление снимка.
3. Не менять `src/`, существующие тесты, публичные сигнатуры, сериализацию и требования к PHP. Реализацию сущностей, маршрутов и валидаторов оставить последующим задачам после согласования контракта.
4. До копирования спецификации провести независимое ревью этой постановки; после изменений — независимое ревью diff. Зафиксировать замечания, решения, точные команды проверок и exit codes.

## Проверки

Сверить `sha256sum docs/openapi/vetmanager_openapi_v6.{yaml,json}` с хэшами выше (exit 0 и точное совпадение). В checkout источника указанного SHA выполнить `python3 scripts/validate_openapi.py` (exit 0; этот скрипт сравнивает распарсенные YAML/JSON и проверяет структуру/operationId/пути). Зависимость — PyYAML; её фактическую версию записать через `python3 -c 'import yaml; print(yaml.__version__)'`. Если валидатор, парсер или сравнение недоступны либо не проходят, PR не считать проверенным. Выполнить `git diff --check` и обязательный `make all PHP_VERSION=8.3` (ожидаемые exit 0). Интеграция на devtr6 не требуется, поскольку исполняемый код и тесты не меняются. CI-матрица PR остаётся самостоятельным гейтом.
