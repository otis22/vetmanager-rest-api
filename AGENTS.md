# Правила разработки для агентов

## Источники и границы

- Перед работой прочитайте `README.md`, `composer.json`, `Makefile`, `.github/workflows/CI.yml` и относящийся к задаче код. Проверьте `git status` и сохраните чужие правки.
- `Roadmap.md` — единая очередь работ; `Tasks.md` содержит зависимости и приёмку. Для нетривиальной задачи сначала создайте или обновите PRD в `PRD/`, свяжите его с задачей и получите независимое ревью PRD до реализации. Замечания и решения зафиксируйте в PRD или задаче.
- После реализации запросите независимое ревью diff. Исполнитель проверяет замечания и фиксирует принятые исправления и причины отклонения. Самопроверка не заменяет независимое ревью.
- Записывайте точные команды, exit codes и ограничения проверок в задаче или PRD. Непройденную или недоступную проверку не называйте успешной.

## Код и совместимость

- Библиотека поддерживает PHP `>=7.3 || ^8.0` (`composer.json`); не применяйте синтаксис новее PHP 7.3 в `src/` и тестах, пока поддержка 7.3 не изменена отдельным решением.
- Пространство имён `Otis22\VetmanagerRestApi\` соответствует `src/`; тестовые наборы лежат в `tests/unit/` и `tests/integration/`, общие помощники — в `tests/Support/`. Сохраняйте публичные сигнатуры и формат `asKeyValue()` / `asString()` без явного требования изменить контракт.
- Следуйте существующему `declare(strict_types=1)`, PSR-12 и типизации проекта. Для изменения поведения добавляйте уместный unit-тест; интеграционные тесты требуют отдельные тестовые учётные данные.
- Секреты и `.env` не добавляйте в git. Используйте только тестовые данные в фикстурах и документации.

## Проверки

- `make all PHP_VERSION=8.3` — Docker: сборка, установка зависимостей, PHPCS, PHPStan, unit-тесты и покрытие 90%. `make help` показывает доступные цели.
- В обычной CI-матрице PHP 7.3–8.3 выполняются `composer validate`, `composer install`, `composer check-style`, `composer check-static-analyze` и `composer unit`. Интеграция запускается вручную через `workflow_dispatch` с отдельными CI-секретами. Пока их пригодность не подтверждена, каждый PR с изменениями исполняемого кода или тестов должен содержать результат локального `make integration` только на devtr6 с числом пройденных и пропущенных тестов. Успешная проверка на 8.3 сама по себе не подтверждает совместимость 7.3.
- `make integration` требует `.env` и доступный тестовый API; не запускайте его на production-учётных данных.

## Git

- Коммит уместен после проверок и ревью. Сообщение кратко объясняет зачем сделано изменение; добавьте `Co-Authored-By: Codex CLI <noreply@openai.com>`.
- Push и PR выполняйте только в рамках поручения. Не используйте destructive reset, amend и force-push без отдельного разрешения.
